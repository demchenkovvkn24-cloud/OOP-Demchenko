Хід роботи
У проєкті lab3v6 реалізовано клас AudioPlayer за варіантом №6 із повним патерном Dispose.
Додано поля для назви треку та стану відтворення, конструктор, а також методи Play() та Stop().
Реалізовано метод Dispose(), захищений Dispose(bool) та деструктор ~AudioPlayer().

У методі Main перевірено три сценарії робочого циклу:
- Через конструкцію using для автоматичного закриття ресурсу.
- Через ручний виклик Dispose().
- Через примусовий виклик GC.Collect(), щоб відпрацював деструктор.

Висновок
Опановано життєвий цикл об’єктів та інтерфейс IDisposable у C#. Конструкція using і метод Dispose() забезпечують миттєве звільнення ресурсів,
тоді як збирач сміття (GC) разом із деструктором роблять це із затримкою. Виклик GC.SuppressFinalize(this)
дозволяє уникнути зайвої роботи GC, якщо ресурси вже були очищені вручну.

Відповіді на контрольні запитання

1. Життєвий цикл об’єкта — це шлях від створення об’єкта в пам’яті через new до його видалення збирачем сміття (GC).
2. Керовані та некеровані ресурси — керовані (пам'ять .NET) GC прибирає сам, а некеровані (файли, мережа, БД) ми маємо закривати вручну.
3. Навіщо IDisposable — щоб швидко звільняти некеровані ресурси, не чекаючи, поки прокинеться GC.
4. Як допомагає using — він сам викликає Dispose(), навіть якщо в програмі стануться помилки.
5. Навіщо GC.SuppressFinalize(this) — каже GC не витрачати час на деструктор, бо ми вже самі все закрили.
6. Чому Dispose(true) і Dispose(false) — true викликаємо ми, щоб почистити всі ресурси, а false викликає деструктор, коли безпечно чіпати тільки некеровані ресурси.
