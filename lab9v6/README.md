Звіт з лабораторної роботи №9

Тема: Поліморфні сервіси: Notification (Email/SMS/Push)

Мета: Застосувати поліморфізм для створення системи сповіщень з різними каналами доставки, навчитися обробляти помилки в поліморфних класах та використовувати списки базового типу для роботи з різними реалізаціями.

1. Короткий опис реалізованої системи (Варіант 6)

У ході виконання роботи було реалізовано поліморфну систему збереження даних StorageService з обробкою помилок та валідацією:

* Абстрактний базовий клас StorageService містить назву сервісу та абстрактний метод Save(string filename, byte[] data).

* Похідні класи:
* LocalStorage — перевіряє наявність вільного місця на диску та зберігає дані.

* CloudStorage — перевіряє наявність мережевого підключення та завантажує дані в хмару.

* FTPStorage — перевіряє коректність адреси FTP-сервера та передає дані.

* Сервісний клас StorageManager містить метод SaveAll, який приймає список базового типу List, поліморфно викликає метод Save для кожного елемента та безпечно обробляє винятки через try-catch.

2. Відповіді на контрольні запитання

* Що таке поліморфізм і як він реалізується через спадкування?
Поліморфізм — це здатність об'єктів різних класів реагувати на однаковий виклик методу по-різному. Через спадкування він реалізується створенням абстрактного базового класу (або віртуальних методів) та перевизначенням цих методів u похідних класах за допомогою ключового слова override.

* Яка різниця між абстрактним класом та інтерфейсом?
Абстрактний клас може містити як реалізовані методи, так і поля стану, але підтримує лише одиночне успадкування. Інтерфейс містить лише оголошення членів без стану та підтримує множинну реалізацію.

* Чому поліморфізм зручний для роботи зі списками різних типів?
Він дозволяє зберігати об'єкти різних похідних класів у єдиній колекції базового типу List і викликати для них спільний метод у циклі без необхідності перевіряти конкретний тип кожного об'єкта.

* Як обробляти специфічні помилки в поліморфних системах?
У кожній реалізації поліморфного методу виконується валідація та генерація винятків (throw Exception). Клієнтський код або клас-сервіс обгортає виклик цього методу у блок try-catch, що дозволяє перехоплювати помилки для конкретного об'єкта та продовжувати обробку інших елементів списку.

* Наведіть приклад з реального життя, де застосовується поліморфізм.
Універсальна платіжна система, де базовий тип "Платіж" має похідні типи CreditCard, PayPal, Crypto. Клієнтський код викликає метод ProcessPayment(), а кожен конкретний тип виконує власну логіку транзакції.
