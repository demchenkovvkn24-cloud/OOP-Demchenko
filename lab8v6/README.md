Звіт з лабораторної роботи №8

Тема: Поліморфізм: динамічне зв'язування та перевизначення методів

Мета: Навчитися реалізовувати поліморфну поведінку за допомогою віртуальних методів та їх перевизначення, а також агрегувати результати поліморфних викликів.

1. Короткий опис реалізованої системи (Варіант 6)

У ході виконання роботи було реалізовано ієрархію класів для роботи з поліморфними стравами Dish:

* Базовий клас Dish містить властивість Name та віртуальний метод Prepare().

* Похідні класи:
* Pizza — перевизначає метод Prepare() та додає властивість Toppings.

* Soup — перевизначає метод Prepare() та додає властивість BrothType.

* Salad — перевизначає метод Prepare() та додає властивість Dressing.

* Агрегація: У методі Main створено колекцію об'єктів базового типу List, у циклі викликано метод Prepare() для кожного елемента та зібрано підсумковий список назв усіх приготованих страв.

2. Відповіді на контрольні запитання

* Що таке поліморфізм і як він реалізується в С# за допомогою virtual та override?
Поліморфізм — це здатність об'єктів різних класів реагувати на однаковий виклик методу по-різному, залежно від їхнього фактичного типу. У C# він реалізується позначенням методу в базовому класі модифікатором virtual, а в похідних класах — модифікатором override для надання власної реалізації.

* Поясніть поняття динамічного зв'язування. Чим воно відрізняється від статичного?
Динамічне зв'язування (пізнє зв'язування) — це визначення того, який саме метод буде викликаний, під час выполнения програми (In Runtime). Статичне зв'язування (раннє зв'язування) відбувається під час компіляції (Compile Time) і прив'язує виклик до типу змінної, а не до фактичного типу об'єкта.

* Наведіть приклад, як поліморфізм дозволяє писати більш гнучкий та розширюваний код.
Якщо в систему потрібно додати нову страву (наприклад, Dessert), достатньо створити новий клас, що успадковує Dish та перевизначає Prepare(). Існуючий код обробки списку страв змінювати не потрібно (дотримується принцип Open/Closed).
* Які переваги дає використання колекцій базових типів для роботи з поліморфними об'єктами?
Це дозволяє зберігати об'єкти різних похідних типів в одній колекції (наприклад, List) та обробляти їх у єдиному циклі, викликаючи спільні віртуальні методи без використання явного приведення типів чи перевірок switch/if.
