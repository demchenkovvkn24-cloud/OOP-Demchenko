Хід роботи

У проєкті IndependentWork3 проаналізовано принципи інкапсуляції та валідації на
прикладі класів UserProfile та OrderItem (за аналогією з архітектурою ASP.NET Core).

Основні рішення в класах:

UserProfile: містить приватні поля _username та _age. У set-аксесорах властивостей додано перевірку значень 
з викликом винятків (ArgumentException для порожнього імені
та ArgumentOutOfRangeException для віку поза межами 0–120).


OrderItem: використовує атрибути DataAnnotations ([Range]) для перевірки кількості та ціни.
Властивість TotalPrice зроблено read-only для автоматичного обчислення суми.

У методі Main створено об'єкти класів, продемонстровано коректне виведення даних та роботу валідації через блок try-catch.

Відповіді на контрольні запитання

1. Ознаки інкапсуляції: приватні поля, доступ через властивості з валідацією та наявність read-only властивостей.


2. Підходи до валідації: ручна перевірка у set-аксесорах із винятками та атрибути DataAnnotations.


3. Посилання на код: необхідні для підтвердження існування класу та аналізу реальної структури проєкту.


4. Висновок з аналізу: інкапсуляція приховує внутрішні дані, а валідація запобігає появі некоректного стану об'єкта.

Висновок

Під час виконання роботи досліджено застосування інкапсуляції та варіанти валідації даних у C#.
Опановано захист полів через set-аксесори з винятками, обчислювані read-only властивості та декларативну перевірку атрибутами.
